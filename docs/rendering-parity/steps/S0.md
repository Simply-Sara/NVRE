# S0 — Archives, load order and file resolution

Each step is one check. `Check` is the command or test that runs it; `Done`
means all five columns of the matrix are filled.

| ID | Step | Check | Oracle | Status |
|---|---|---|---|---|
| S0-1 | Every BSA the game's own `SArchiveList` names opens, and every entry in it is readable | `cargo run -p nvre-editor --bin schema_coverage` already walks the VFS; add an archive-summary mode that prints per-archive entry counts and read failures | O4 | FNV/FO3/Skyrim done; FO4 BA2 done; LE/SE BSA done |
| S0-2 | A loose file beats the archive of the same name, and the *last* archive in list order beats the first | VFS unit test over a synthetic pair; then confirm against a real mod that overrides a base texture | O4 | to write |
| S0-3 | The load order the editor computes equals the order the game's launcher writes | `crates/nvre-editor/tests/plugin_order.rs` — extend to assert the full order for all five games, not FNV alone | O1 | to extend |
| S0-4 | `winner(lo, fid)` resolves every FormID the corpus's cells reference, with no unresolvable reference rendered as an invisible placeholder | corpus walk: count refs whose base resolves, per game | O4 | to write |
| S0-5 | A mesh path that names `data\textures\...` or an absolute path resolves, as the engine strips it | `nvre-vfs::texture_path` unit test, then a corpus count of paths needing each form | O2 | partially covered |

**Why S0 is first even though it is boring:** every later stage's numbers are
conditional on reading the right bytes. A decode that is "wrong" only because
it read a mod's override instead of the base file is a false positive that
costs a day to chase.
