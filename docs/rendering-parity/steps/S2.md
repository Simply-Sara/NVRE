| ID | Step | Check | Oracle | Status |
|---|---|---|---|---|
| S2-1 | Every shape is reachable from exactly one root, and no node has two parents in the resolved graph | corpus walk over `scene_objects` (`nifgraph`) and `model::world_transform` single-root traversal | O4 | **verified**: verified via `nifgraph` and `model.rs` ancestors tracking |

| S2-5 | The `name` of every node and shape survives the string-table resolution, because `EditorMarker*` detection and skin binding both key off it | `corpusresolve` counts nodes and shapes with a name, and names still an index, per game | O4 | **verified**: FNV 629,943/629,943 FormIDs resolve; 8,768/8,773 nodes named; the 5 unnamed were Bethesda's null-string sentinel `0xFFFFFFFF`, now resolved to the empty name (nifgen reads the same) |

**Note on S2-3.** This is the one place in S2 where a wrong answer looks like a
geometry bug downstream — a model that is correctly shaped but mirrored or
sheared. It is worth a test of its own rather than being folded into S3.

**Note on S2-2.** The root's transform is the last link in the chain of
ancestors, so it is already inside a shape's own transform. Multiplying it
in again — which the model's bounds did — puts the bounds of a model whose
root is translated twice as far out as its geometry is. The bounds are what
the viewport picks a reference with, so the symptom is a click that misses.
