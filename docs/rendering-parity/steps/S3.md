**Why S3-3 and S3-4 are separate.** They are the two packed formats, they
differ in exactly the position field, and the flag that distinguishes them is
*not* reliable on its own — every Skyrim SE desc clears `FULL_PRECISION` and
still stores full floats. Conflating them is how a half-precision position
gets read as a float and every vertex lands on the origin.

**Why FO4's no-UV count is 540,965 of 662,902.** It is not a defect in the
reading. FO4 stores pre-combined static geometry under `meshes\precombined`,
and there the vertices live in a shared `BSPackedCombinedSharedGeomDataExtra`
block — an `NiExtraData` carrying its own `vertex_desc`, `num_vertices`,
`num_triangles` and per-object `BSPackedGeomObject` records. The `BSTriShape`
blocks in those files are stubs: `data_size` 0, a `num_vertices` that is
declared but not carried, pointing at the shared block instead. So a shape
there reads as having no positions and no UVs, which is the same reason S3-8
reports 8,857 vertex-count mismatches for FO4 and none for the other four.

The geometry is present in the file; the reader does not yet assemble it from
the shared block. That is a known gap, recorded here so the number is not
mistaken for a decode failure — and it is also why a small sample of FO4 looks
clean: the VFS is sorted, so a few thousand files cover `meshes\actors\a...`
and never reach `precombined`. A whole-corpus walk is the only way this shows
up, which is the argument for running one.
