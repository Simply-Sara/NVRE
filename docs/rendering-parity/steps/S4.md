# S4 — Material decode

This is the stage with the most known defects, because it is the stage whose
output is a *judgement* rather than a value: a field that is read into
`ShapeProps` but never consumed is invisible until something draws wrong.

| ID | Step | Check | Oracle | Status |
|---|---|---|---|---|
| S4-1 | **The consumed-field census.** For each game, for each property block type that appears in the corpus, list every field the schema declares on it and whether `shape_props` reads it. Output `read / ignored / not-applicable`, and every `ignored` gets a one-line reason or becomes a defect | new checker `fieldcensus`: schema block fields × the names `shape_props` calls | O4 | generated: `docs/rendering-parity/corpus/s4-1-consumed-field-census.txt` across all 5 games |
| S4-2 | `BSLightingShaderProperty` — every lit Skyrim shape — is dispatched on, not just read by the generic path | extend the `match` in `shape_props`; unit test a Skyrim shape's flags reaching the props | O2 | **defect: no match arm** |
| S4-3 | `alpha_mode` is exhaustive and exact: all 8192 combinations of the 13 meaningful `AlphaFlags` bits, tabulated against fopdoc's documented layout | unit test enumerating the domain; the existing `alpha_mode` tests are the seed | O2 | 8 cases tested of 8192 |
| S4-4 | The same table is checked for **Skyrim's `AlphaFlags`**, which is a different bit layout from Fallout's | per-game enumeration; the two layouts must not share one `alpha_mode` | O2 | to verify |
| S4-5 | `NiStencilProperty`'s draw mode is read from the right field per version — `draw_mode` before 20.1.0.3, packed into `flags` after | unit test both versions; corpus count of shapes that are double-sided per game | O2 | both paths implemented, one branch untested |
| S4-6 | The texture set's slots are read as 0 diffuse, 1 normal, 2 glow, and an empty slot is a slot that is not used | `texture_set` unit test; corpus count of shapes with a glow slot per game | O2 | implemented, untested |
| S4-7 | `emissive_mult` and `emissive_multiple` are both read, and a property with neither is 1.0 | already unit-tested (`either_spelling_of_the_multiplier_reads`); extend to assert no shape in the corpus reports a multiplier of exactly 0.0 with a non-zero emissive colour | O4 | tested |
| S4-8 | The falloff is applied only where the flags switch it on, and only on a shape that blends | `Falloff::from_fields` tested; corpus count of shapes with falloff fields, split by flag bit 6 and by blend mode | O4 | tested, not measured |
| S4-9 | `vertex_alpha` is read from the right bit per path: bit 3 lit, bit 19 unlit | corpus count of shapes taking each bit, per game; assert no shape loses its alpha to the wrong bit | O2 | both bits read, distribution unmeasured |
| S4-10 | `shader_flags_2` — zbuffer write, LOD, vertex colours, premultiplied alpha, refraction tint — is read at all | new checker printing the flag histogram; then decide each bit's effect and record it | O2 | **not read anywhere** |
| S4-11 | `NiVertexColorProperty` — whether vertex colours tint the shape — is in the schema and read, or is absent from the schema and the shapes that carry it are counted | `props.vertex_colors` is assigned and **never consumed**; either wire it into the material or delete it, and count the shapes affected | O4 | **defect: assigned, unused** |
| S4-12 | `TexDesc`'s texture transform (translation, scale, rotation, centre) is either applied or explicitly declared out of scope with a count of the shapes that carry one | corpus count of `has_texture_transform` per game | O2 | **not read anywhere** |

**The census is the point of this stage.** S4-1 is not one check among twelve —
it is the check that generates the rest. Every field marked `ignored` is either
a decision that gets written down or a bug that gets a step of its own, and the
list is finite because the schema is finite.
